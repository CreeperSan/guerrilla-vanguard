# 开发顺序与验收清单

这份清单用于把策划变成可执行任务。当前均未验收；不要因为文件里有脚本名就勾选完成。原型问题见 [复核记录](DESIGN_REVIEW.md)。本次只改文档，不附带代码重构。

## 1. 工作方法

每次开发只选一个里程碑中的一个可见结果。先复现当前行为，再修改，完成后在下表记录验收结果与问题。前一个里程碑不过，不并行开新系统。

推荐单次任务格式：“完成某个具体行为；使用哪些已有场景；不扩展哪些范围；运行哪个验证场；满足什么条件算完成。”例如第一步只修复生命与玩家预制体，不把任务写成“实现完整 Roguelike”。

所有工作量为相对判断：小=一项局部规则；中=多个节点与 UI 联动；大=跨房间/跨场景状态，需要拆分。不给缺少经验依据的工期承诺。首作优先每个阶段都有能玩的结果。

## 3. 每阶段必须验证的行为

### M0：组件和场景一致

- [ ] Health 治疗真正增加生命；不超过上限，伤害不降到负数。
- [ ] 死亡后重复伤害不会重复发奖或重复死亡。
- [ ] 子弹命中敌人仅伤害一次，命中墙消失，不伤同阵营。
- [ ] 正式关卡与 TestLevel 使用同一个玩家预制体；无缺子节点错误。
- [ ] 已有移动与八方向动画仍正常；不顺手更换素材或控制方案。

### M1：战斗可读且不会卡死

- [ ] 按住 J 按间隔射击，松开立即停止；不同帧率下射速不随帧率加倍。
- [ ] 空匣不能射击，R 正常消耗备弹；手枪零备弹可完成紧急换弹。
- [ ] 玩家受伤闪烁，0.6 s 内后续命中不扣血；暂停冻结计时和子弹。
- [ ] 3–5 敌人按前摇攻击，远程弹可躲；清敌开门，死亡进入失败界面。
- [ ] 封门时不会把玩家挤出边界；开门后无残留敌弹继续伤害玩家。

### M2：成长与存档可靠

- [ ] 未清房就死亡没有清房情报；清房后死亡全额保留该房情报。
- [ ] 成功撤离、阵亡、主动放弃各自正确结算；物资不转成情报。
- [ ] 连点结算按钮、重复死亡信号、重复清房信号不多发货币。
- [ ] 买一级生命升级，扣正确情报，下次出击生命上限改变；余额不足不扣钱。
- [ ] 在出击后、清房后、结算前后分别关闭并重开，情报不重复、不因正常重启丢失已保存上传量。
- [ ] 主档损坏能尝试备份；保存失败明确提示且不显示成功。

### M3：枪械、道具和经济

- [ ] 五枪的射速、弹数、射程、换弹、备弹上限与数值表一致；狙击高速弹不穿过目标。
- [ ] 霰弹一次消耗 1 发、生成 5 弹丸；同敌可吃多弹丸伤害。
- [ ] 切枪取消装填且不刷新冷却；满槽/选中手枪/重复枪各按既定规则处理。
- [ ] 突击兵攻击可打空；重装兵参数独立，未额外发明第三套远程 AI。
- [ ] 医疗满血、手雷满额、弹药满额时不消耗物品；商店不扣款。
- [ ] 商店库存回房不刷新；免费武器库物品各领一次；重复操作不复制枪或弹药。
- [ ] 三项强化各三阶、四枪解锁、额外出击一枪均正确；最高等级不能继续购买。

### M4：随机地图与三关

- [ ] 固定六房先走通所有门，再开放随机；重入不刷敌和奖励。
- [ ] 6/8/10 房全部通过每种 1000 种子的结构验证。
- [ ] 九种尺寸都实际进入试玩，四种进门方向的出生点/门口/镜头正确。
- [ ] 第 1/2/3 关分别为 6/8/10 房，功能房各四间，敌种递进正确。
- [ ] 任意出口路线至少通过 1/2/3 战斗房，仍存在可跳过的支线。
- [ ] 同关模板不重复，跨关可复用；分支与环路都能生成。
- [ ] 跨关保留生命与背包，不可返回旧关；只有普通第 3 关撤离才发 32 额外情报与最终资格。
- [ ] 调试强制生成失败时，有有限重试和可用兜底，不无限转圈。

### M5：首领与胜负

- [ ] 首次普通通关同时永久解锁和授予一次资格；多次通关资格仍最多 1。
- [ ] 资格可跨重启保留；最终开局只扣一次，未完成加载的程序错误按约定退还。
- [ ] 最终任务新行动满血、重新配装，不能继承普通行动的局内枪和物资。
- [ ] 首领低于半血仅切阶段一次，二阶段两单发一扇形，不同时叠招。
- [ ] 最终失败情报保留但资格用尽，需重打普通三关；已有永久解锁不会消失。
- [ ] 胜利首领奖励只发一次；同归于尽按失败，不同时打开胜负界面。
- [ ] 结局能关闭并回指挥部，重开保留已通关标志。

## 4. v1.0 发布门槛

- [ ] 干净新档从主菜单完成至少一次“失败→升级→普通通关→最终胜利”。
- [ ] 一个已有进度存档完成“继续普通行动→最终失败→重新普通通关→最终重试”。
- [ ] 收集数值文档要求的试玩记录；没有无弹死局、不可达门、负货币、重复奖励或无法退出界面。
- [ ] HUD 能分清永久情报、本轮情报、本轮物资；未实现的支援按钮不出现。
- [ ] 所有交互有按键提示；设置能控制声音；射击、受击、死亡、清房、购买和胜负有基本可辨反馈。
- [ ] 不要求重新绘制全部素材；占位色块必须区分敌种、子弹和可交互对象。
- [ ] 在开发者 macOS 导出包中，从 Finder 启动验证窗口、输入、暂停、存档与退出；不是只在编辑器测试。
- [ ] 连续玩三次行动没有阻断流程的报错；一般警告记录并逐项判断，不盲目追求控制台零文本。
- [ ] 确认随包素材的使用许可，记录素材来源；不要求为首版制作完整原创素材。

不在这一步增加成就、额外敌种、商店刷新和联网。只修复阻断、明确操作问题及明显数值失衡。

## 6. 风险与对应限制

| 风险 | 固定处理方式 |
| --- | --- |
| 随机地图拖住整个项目 | M4 先固定图，再抽预验证图；不换成自由矩形摆放算法 |
| 配置越写越像大型引擎 | 只抽离当前用到的字段；没有第二种用途前不做通用插件层 |
| 五枪、九尺寸增加工作量 | 枪共用投射与换弹；房间共用墙门与地板，不做独立美术主题 |
| 子弹/死亡/结算重复触发 | 唯一伤害入口、死亡保护、奖励 ID 与结算 ID 去重 |
| 战斗时长不足预期 | 接受更短的成品；先看玩法闭环，不增加刷取门槛 |
| 最终失败后重打令人疲劳 | 先按当前规则实现并测；若要改为直接重试，作为明确的体验决策改文档，不暗改资格逻辑 |
| 想到新功能就推翻旧版 | 写入后续想法区，不进入当前验收；完成当前里程碑后才评估 |
