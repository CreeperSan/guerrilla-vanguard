# 关卡制作与扩展约定

本文件约束实现方式，避免首作变成地图算法或通用框架项目。它是设计方案，不表示相关代码已完成。

> 当前房间和路线规则以第 6 节为准；第 1–5 节中较早的固定房间数、尺寸和 Boss 流程属于历史基线，与本轮六关路线冲突时不再适用。

## 1. 随机地图：先选可靠结构，再填内容

采用**单房间加载 + 逻辑地图 + 预验证布局模板**。走门后淡出切到邻房，保留玩家本轮状态；不是无缝拼接世界。随机房间组合和支路仍然成立，但不需要做任意矩形在无限网格中的放置、走廊寻路和实时门洞切割。

一关生成步骤：

1. 根据任务与关卡序号读取房间数、敌群、情报奖励和出口类型。
2. 从该房间数的有效布局模板中随机选一种，再随机旋转/镜像其逻辑坐标和门方向。
3. 在指定的入口、商店、武器库、出口位置分配功能房；剩余位置全为战斗房。最终路线末关用首领房替代出口。
4. 从 9 个战斗模板中无放回抽取需要数量，每个模板 ID 同关最多一次；功能模板各用一次。原型阶段可以临时重复，正式版必须校验。
5. 为战斗房抽 3–5 敌人数、配置出生点；为商店与武器库预抽库存。全部使用本关固定种子，不在进门时重抽。
6. 校验房间数、模板唯一、连通、双向门、入口到出口必经战斗数量、出生点；通过后进入入口房。

v1.0 每种房间数只需两种连边变体，旋转/镜像再增加视觉变化。v1.1 为 7/9 房补配置即可，不更换生成器。

### 可直接制作的模板族

节点 0=入口、1=战斗、2=出口、3=商店、4=武器库、5=战斗；新增的 6/7/8/9 均为战斗。

基础 6 房坐标：0=(-1,0)、1=(0,0)、2=(0,-1)、3=(1,0)、4=(1,1)、5=(0,1)。必需边为 0–1、1–2、1–3、3–4、4–5。

- 变体 A：再加 5–1，形成环路。
- 变体 B：不加 5–1，形成支线树。两者都存在分支，不要求每局一定有环，但发布版本必须实际能抽到环路布局。
- 7 房：用 1–6–2 替换 1–2，6=(0,-1)、2=(0,-2)。
- 8 房：基于 7 房，加 7=(2,0)，连 3–7。
- 9 房：基于 8 房，用 6–8–2 替换 6–2，8=(0,-2)、2=(0,-3)。
- 10 房：基于 9 房，加 9=(2,1)，连 7–9；变体 A 再连 9–4，变体 B 不连。

边都连接相邻格，最大门数不超过 4。使用每个节点独立的房间场景，不需要把这些坐标乘像素后生成连续地形。相邻但没有图边的两房不连接，关闭对应门。

| 流程关卡 | 房间数 | 战斗房数 | 任何入口到出口路径至少经过战斗房 |
| --- | ---: | ---: | ---: |
| 普通 1 | 6 | 2 | 1 |
| 普通 2 | 8 | 4 | 2 |
| 普通 3 | 10 | 6 | 3 |
| v1.1 最终 1 | 6 | 2 | 1 |
| v1.1 最终 2 | 7 | 3 | 2 |
| v1.1 最终 3 | 8 | 4 | 2 |
| v1.1 最终 4 | 9 | 5 | 3 |
| v1.1 最终 5 | 10 | 6 + 独立首领房 | 3，再到首领 |

表中“6 + 独立首领房”表示 6 普通战斗房加 1 首领房；本关仍只有 10 房：入口、商店、武器库、首领、6 战斗。v1.0 最终任务为单首领节点，不运行上述普通布局校验。

路径约束用带权最短路径检查：进入战斗节点代价为 1，其他为 0，入口到出口最小代价不得低于表中值；不能只检查最短边数。功能房不设钥匙或全清门槛；支路始终可选。

### 九种规格与门口

一个尺寸单元为 500×500 世界单位，宽高各取 1/2/3：1×1、1×2、1×3、2×1、2×2、2×3、3×1、3×2、3×3。NxM 房间的可活动区域为 N×500 乘 M×500；外墙厚度计入房间模板边界，不额外改变逻辑占地。每个 500 单位边段预留一个门位，因此 1×2 房间上、下各 1 个门位，左、右各 2 个门位。相邻房间在地图中留出 72 单位间隔，门位仍按逻辑路线对应；进入门区后传送到另一房间的对应入口。未清除本房间全部敌人时，门洞门板保持碰撞。

每个房间在整数网格中占据真实 NxM 矩形；候选位置必须与已有房间不重叠，并与至少一个房间共享完整的 500 单位边段。共享边界按每个单元槽计算门位，路线边和实体门位由同一张邻接表导出。房间场景在首次进入时才生成敌人、木箱、水域和拾取物；未访问房间只保留静态墙地与门区。小地图按房间矩形占地绘制，并标明连接、当前房间、已访问房间、起点和 Boss 房。

房间不旋转美术，只旋转逻辑门映射，避免角色贴图和出生点随意旋转。每个模板提供四个玩家入门落点，至少 5 个敌人点，1 个武器/补给安全点；敌人点按本次入口筛掉距玩家小于 120 px 的点，仍需有至少 5 个可用点，否则该模板不合格。可以提供多于 5 点；1×1 小房也必须验此条件。

同一场景使用共同房间基类和图块，不复制战斗脚本。房间内不放实体内墙，不制作门廊迷宫。不同尺寸引入镜头跟随与边界限制：设计视口按 640×360 起步，窗口缩放不改物理单位；小房中心固定镜头，大房跟随玩家并限制在房间边界。可见范围外的射手不能开始攻击；已发射弹正常飞行，减少大房屏外偷袭。

### 最低内容清单

| 资产 | 数量 | 制作办法 |
| --- | ---: | --- |
| 战斗模板 C11 到 C33 | 9 | 每种尺寸一个，复用图块；色块/装饰区分，无内墙 |
| 入口 / 商店 / 武器库 / 出口 | 各 1 | 1×1，改变交互对象和标识 |
| 首领房 | 1 | 2×2，空旷场地，玩家与首领出生点独立 |
| 普通布局 | 6 配置 | 6/8/10 房各 A/B 变体 |
| 扩展布局 | 4 配置 | v1.1 加 7/9 房各 A/B 变体 |

总计 14 个房间模板，不需要制作 24 或 40 个独立场景。同关最多 6 个普通战斗房，9 个模板足够无重复抽取；跨关允许复用。模板 ID 不能只改名来伪装“不重复”。

## 2. 房间状态与切换

房间运行状态只有未进入、战斗中、已清理；功能房第一次进入即视为安全。进入战斗房时先建立全部敌人，再启动开战预警。计数归零触发一次清房，按唯一敌人 ID 去重死亡事件。

门交互流程：验证可通行 → 暂停输入 → 保存当前房间库存/拾取状态 → 清除投射物和临时效果 → 加载目标房 → 把玩家放到对应门内落点 → 恢复输入。切房后 0.3 s 禁止再次触门，且需要离开门触发区才能再次触发；不能往返抖动或重复结算。

只保留一个活动房间。内存中的 RoomState 保存是否已清理、敌群抽签结果、剩余补给和库存；已清理房间重入不生成敌人。本轮不做磁盘场景快照，避免与“不支持局内续玩”矛盾。

出口按 E 确认离开本关；下一关是新地图，上一关状态释放。本关奖励与库存的唯一性由房间 ID + 奖励 ID 保证。

## 3. 适量的扩展接口

优先使用少量 Godot Resource 或统一配置表。选一种即可，不同时维护 JSON、Resource 和脚本常量三份数值。不先做插件、编辑器工具、事件总线、ECS 或可插拔 mod 系统。

| 数据 / 组件 | 最小职责 | 后续如何扩展 |
| --- | --- | --- |
| WeaponDefinition | 稳定 ID、伤害、间隔、弹匣、备弹、换弹、弹速、射程、弹丸角度 | 同一种投射逻辑即可支持五枪；未来新机制再新增行为 |
| EnemyDefinition | 稳定 ID、生命、移速、攻击参数、掉落 | 步兵/重装共用行为，突击兵单独近战行为 |
| ConsumableDefinition | ID、价格、上限、效果类型与参数 | v1.1 新增火区/免伤效果实现；无需改货币和商店逻辑 |
| ItemEffect | 使用前验证、成功后扣数量，失败不扣 | 导弹/空投独立效果场景，不把效果全部塞入玩家脚本 |
| RoomDefinition | ID、尺寸、场景、门、出生与补给点 | 新房间只新增定义和场景 |
| StageDefinition | 房间数、布局集合、敌群、倍率、清房情报、出口种类 | 普通和最终用同一关卡控制器 |
| MissionDefinition | ID、有序关卡列表、开始资格、通关奖励 | v1.0 最终列表为一个 boss_only；v1.1 换成五个 stage，末尾 boss |
| Player / Health / WeaponManager | 移动动画 / 生命 / 武器状态和开火 | 延续原型拆分，不重写整个人物系统 |
| RoomController | 门、敌人生成、清房、补给 | 不负责永久存档或指挥部 UI |
| RunManager | 本轮任务、玩家战斗状态、物资、情报、地图、结算 | 不把局外强化逻辑塞进房间 |
| ProfileStore | 永久余额、升级、解锁、资格与可靠保存 | 存档迁移独立于 UI |

可以只把 RunManager 和 ProfileStore 作为跨场景常驻对象，其他由场景持有。UI 读取状态并发请求，不自行扣钱、增加生命或结算。一次购买必须完成“校验 → 扣费 → 给物品/升级 → 保存/通知”这一条路径。

信号保持局部、可追踪，例如生命变化、死亡、武器变化、房间清理、本轮结束；不创建任何对象都能广播任意字符串的全局事件系统。

碰撞职责先统一：子弹识别有效目标后通过一个入口调用 Health，设置已命中标记再销毁；HurtBox 不再重复扣血。墙体同时处理，友方 HurtBox 忽略。高速狙击弹必须验证穿过一帧位移路径的碰撞，可用移动段检测补足，不能只看终点重叠。

## 4. 存档、结算与扩展迁移

只保存单档永久进度和防丢情报日志。稳定 ID 使用字符串（如 pistol），不持久化易随插入项改变的枚举序号或场景节点路径。

建议存档结构：

```text
schema_version: 1
profile:
  intel_balance: 整数
  upgrades: { health: 0..3, pistol_damage: 0..3, supplies: 0..3 }
  unlocked_weapons: [稳定 ID]
  selected_start_weapon: 稳定 ID 或空
  final_unlocked: 布尔
  final_ticket: 0 或 1
  ending_seen: 布尔
pending_run:
  run_id: 唯一 ID
  mission_id: 普通或最终
  credited_intel: 本轮已上传但未入永久余额的情报
  awarded_event_ids: 已上传奖励的唯一 ID 集合
  seed: 随机种子，仅用于诊断
last_settled_run_id: 最近已结算 ID
settings: { master_volume: 0..1 }
```

没有进行中的行动时 pending_run 为空。出击先写 pending_run，最终任务同时扣 ticket；写入成功后才加载关卡。每次清房或通关情报生成，都将奖励 ID 去重后累加并保存。保存失败时保留当前内存状态、暂停流程并提供重试提示，不显示“已保存”或静默继续消耗资格。

正常结算在同一次存档写入中：把 pending 情报转入余额、记录已结算 ID、更新普通成功的永久解锁和资格/最终成功的结局标记、清空 pending。失败和主动放弃只转入已上传情报。重启看到 pending 则按中断恢复，只转入情报，不发新的通关奖励，不恢复资格。若成功奖励已上传但尚未完成成功结算，则保留该笔情报，仍按中断处理；避免推测出未经保存的胜利状态。

写入位置使用 Godot 的用户数据目录；临时文件完整写入并验证后替换正式文件，保留上一次有效备份。读取先检查格式、版本、非负货币和等级上限；主档无效尝试备份。两者均坏时提示恢复失败，须由玩家选择新档，不静默覆盖旧文件。未知武器 ID 忽略，所选初始枪无效则回到仅手枪。

ProfileStore 串行执行写入请求，不允许清房保存、购买保存和结算保存同时覆盖彼此。保存失败后的重试使用原奖励/结算 ID，不重新生成一笔收入。

v1.1 若仅新增数据配置无需提升存档 schema；若新增必须持久化的字段则升级版本并提供迁移函数，给缺省值，保留情报、等级、解锁、资格和通关标志。新增道具和支援属于局内库存，不为了它们保存整局。至少保留一个 v1.0 存档样例做迁移验收，不通过删除旧档解决兼容问题。

## 5. 随机与配置验证

同种子 + 同一内容版本应得到同地图、敌群和库存。布局、敌群、掉落使用独立随机流或预抽取，不能因为玩家提前购物改变后面敌人。不要跨内容版本承诺种子结果完全相同。

## 6. Boss 房与六关路线生成（本轮补充）

- 每关由起点房、普通房和唯一 Boss 房构成。普通房不实例化 Boss；Boss 只在 Boss 房生成。
- 房间尺寸固定为 500 世界单位的整数倍，提供 1×1 到 3×3 共九种尺寸。每种尺寸至少有两种场景样式，目录按 `Room_1x1_01/Room_1x1_01.tscn` 命名；生成器自动扫描所有编号，少于两种会提示补齐，多于两种会全部保留并参与随机。模板共用墙、地面、门和战斗逻辑，不复制脚本。
- 关卡开始时按种子一次性生成路线和占地。先生成起点到 Boss 的主路径，再放置普通房分支；矩形摆放后扫描真实相邻边界，普通房间之间可自然形成闭环。Boss 为主路径末端，不允许从 Boss 再向外连接。
- 主路径长度按移动的房间边数计：Level 1–2 为 2–4；Level 3–4 为 2–5；Level 5–6 为 3–6。移动上限优先于房间总数，分支不增加主路径长度。
- 候选房间在整数网格中摆放；碰撞的占地拒绝，只有相邻边界真实重合才可连门。生成后检查起点到 Boss 的最短路/主路径边数、房间可达性、占地无重叠、门两侧一致、Boss 度数为 1。最多尝试 8 个种子，失败使用带普通房闭环的静态合法兜底布局。
- 房间首次进入时才创建敌人、木箱、水池和拾取物；房间内所有敌人清除后打开门板，门区将玩家传送到路线另一端。Boss 房需清除 Boss 和守卫后才开放中心出口。摄像机只显示当前房间范围，并仅在房间传送时平滑过渡。只有接触已开放的 Boss 出口才结算本关并进入下一关；Level 6 Boss 出口完成最终结算。
- UI 小地图依据同一份生成数据展示物理占地矩形和连接；进入新房时更新当前房间，已访问房间保留状态。小地图不单独随机或重新推导路线。

暂定随机策略：每次新开一局生成一次；Level 1–2 最少两步。种子保留在本局状态中，以便重现问题。

发布前对每种受支持房间数跑 1000 个种子：房间数量准确、模板唯一、所有房从入口可达、双向连接一致、每房最多四门、无重复坐标、必需功能房各一、无绕过最低战斗数的路径、敌数与出生点合法。抽检必须覆盖九种房间规格、两种布局、四个入门方向和首领替换出口。

生成无效时只允许有限重试（最多 8 次）；随后使用该房间数的已验证固定 A 布局与固定模板分配，记录种子与失败原因。兜底内容本身也必须校验；兜底仍失败则显示可返回指挥部的错误，不加载半张地图、不无限循环。本轮因生成错误中止仍结算已获取情报；如果是最终任务开局前的加载/配置错误，退回刚扣的资格，避免把程序错误当作战败。
