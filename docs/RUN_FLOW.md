# Roguelike 对局关卡流程

## 规则梳理

- 一局的 Level 路线是一条有序直线，在开局时一次性随机确定，通关后只能推进到下一关。
- 空降模式从随机池不重复抽取 5 关；总攻模式不重复抽取 6 关，再追加固定的地下要塞作为第 7 关。
- 随机池为：要塞、丛林、村庄、山谷、都市、矿井。地下要塞不参与任何模式的随机抽取，仅作为总攻固定终点。
- 总攻末关对应实际目录 `LevelUndergroundFortress`（用户补充中的 `LevelUndergroundFortness` 为同一关卡）。
- 本局关卡序号与主题身份分开。例如第 1 关可以是矿井，第 5 关可以是丛林；总攻第 7 关始终是地下要塞。
- 房间生成规则仍由本局关卡序号决定：第 1～2 关 2～4 次、第 3～4 关 2～5 次、第 5～7 关 3～6 次移动可达 Boss。分叉、普通房环路、Boss 末端、500 单位尺寸、懒加载、清场锁门规则保持。
- 每个 Level 清空 Boss 房守卫并击败 Boss 后，触碰 Boss 出口才算完成；仅击败 Boss 不直接切关。
- Level 之间保留玩家、生命、武器弹药、装备、支援、技能与积分；清理上一关的房间和临时战斗效果。
- 完成最后一关进入胜利状态；玩家死亡进入失败状态。这两种状态都停止推进，重新开始会创建新的玩家和路线。
- 同一模式、主题池和种子可复现 Level 顺序与每关房间种子。未指定种子时每局随机。
- 当前不包含跨进程存档和中途继续游戏。

## 职责与接口

`GameManager` 作为 AutoLoad 全局单例，只负责本局流程：主题池校验、随机抽取、当前序号、关卡种子、推进锁、胜败状态和进度快照。它不生成房间，不持有玩家背包副本。

`FortressLevelController` 继续管理单个 Level 的地图与内容。正式对局使用一份持久的 `GameRun.tscn`，由 GameManager 发出切关请求，控制器更换主题和地图后确认就绪，避免每关重新创建玩家和 HUD。

HUD 只显示 GameManager 的同一份快照：模式、当前主题、关卡序号、整条主题路线、完成数和进度。房间小地图仍表示当前 Level 内部路线。

| 接口 | 用途 |
| --- | --- |
| `attach_level_host(host)` | 绑定处理关卡请求的场景控制器 |
| `start_run(mode, seed, pool)` | 开始空降或总攻模式；未传池时使用全局配置 |
| `get_run_snapshot()` | 获取供 HUD、调试和其他系统读取的进度副本 |
| `confirm_stage_ready(host, stage_number, revision)` | 控制器确认对应版本的关卡已经生成完成 |
| `is_stage_request_current(host, stage_number, revision)` | 异步清理后校验加载请求，避免旧请求覆盖新局 |
| `report_level_cleared(host, stage_number)` | 安全出口触发后请求推进；校验来源、序号、房间安全和重复调用 |
| `fail_run(host)` | 玩家死亡后结束本局 |
| `restart_run()` | 清空本局并重载正式对局场景，回到模式选择 |

## 状态

| 状态 | 允许的操作 |
| --- | --- |
| IDLE | 选择模式、开始新局 |
| TRANSITIONING | 等待指定关卡生成确认，拒绝重复通关 |
| ACTIVE | 进行战斗，安全出口可请求推进，死亡可结束 |
| COMPLETED | 显示胜利和最终进度，允许重新开始 |
| FAILED | 显示战败和本局进度，允许重新开始 |

开始和推进时先进入 TRANSITIONING，再请求场景加载；只有收到当前关卡的就绪确认才进入 ACTIVE。延迟请求带版本号，重新开始或失败后忽略上一局的过期请求。`start_run` 只在 IDLE 接受请求；完成或失败后使用 `restart_run` 重建玩家，避免带着上一局的背包重新抽取路线。

## 测试入口

正式入口为 `Scene/GameRun/GameRun.tscn`，也设置为项目主场景。进入时选择空降 / 总攻模式，再执行已有的 3、2、1 倒计时。其余主题场景可继续用 F6 独立测试单关。

主题池配置为 `Script/Level/run_level_pool.tres`，新增主题时将其 `BattlefieldTheme` 加入池。GameManager 单独配置 `full_assault_final_theme`，并从随机候选中排除其目录。池内空值和重复目录会被排除，随机池不足 5 / 6 个主题时明确报错，不隐式重复关卡。

`GameRun` 根节点的 `run_seed` 为 0 时随机；改成固定整数便于复现。

### 自动测试

先由 Godot 导入项目，再运行流程测试（将 `godot` 替换成实际可执行文件路径）：

```sh
godot --headless --path . --editor --quit
godot --headless --path . --script res://tests/run_flow_test.gd
```

测试验证 5 / 7 关、不重复抽取、地下要塞从随机池排除、总攻固定末关、固定种子复现、不同种子变化、主题池不足、来源与序号校验、切关等待确认、重复通关拒绝、最后一关完成、失败后禁止推进和重新开始后的请求失效。自动测试使用模拟关卡宿主，不代替真实房间、触控和画面测试。无效配置用例会故意输出错误日志；最终应输出 `failures=0` 并以退出码 0 结束。

### 实机检查

1. F5 运行项目，选择空降，检查进度面板显示 5 个路线节点、当前 1/5、完成 0/5。
2. 结束后重新开始，选择总攻，检查显示 7 个节点且主题无重复，最后固定为地下要塞；空降路线中不应出现地下要塞。多开几局观察前面的顺序变化。
3. 清空 Boss 房并击败 Boss，然后触碰中央出口：只能前进一次，完成节点变绿，当前节点高亮，房间小地图更换。
4. 切关前后比较玩家生命、武器弹药、装备和积分，确认继续保留；上一关子弹和支援效果应被清理。
5. 完成最后一关，应显示胜利和总积分，进度为 5/5 或 7/7，不再生成新关卡。
6. 中途死亡，应显示战败并停止推进；重新开始后玩家和路线均重建。
7. 将 `run_seed` 设为同一个整数，选同一模式两次，比较输出日志中的路线及各关种子；应完全一致。
8. 分别用键盘、手柄、触控选择模式，确认倒计时期间无法移动和射击，路线面板和房间小地图互不遮挡。
