# Guerrilla Vanguard 开发文档

当前实施基线：**2026-09-29 / v1.0 首版 + v1.1 扩展计划**。

目标是完成第一个 Godot 游戏：先让开始、战斗、失败、成长、最终胜利形成稳定闭环，再扩充内容。不是以独创性、市场表现或长游玩时间为验收标准。

## 阅读顺序

1. [游戏策划](GAME_DESIGN.md)：故事、版本范围、操作、完整流程和所有交互规则。
2. [数值与经济](BALANCE.md)：角色、武器、敌人、奖励、商店、永久成长及试玩方法。
3. [关卡与扩展约定](LEVEL_AND_SYSTEMS.md)：随机地图的低风险做法、房间清单、系统边界、存档。
   - 该文档的第 6 节记录了六关 Boss 路线、500 单位矩形房间、每种尺寸至少两种样式的目录规则与门位规则；生成器、`FortressLevel.tscn` 运行控制器和模板位于 `Scene/LevelFortress/`。
   - [多主题关卡与键盘操作](LEVEL_THEMES.md)：六个主题关卡入口、主题配置、素材目录，以及 WASD 移动与方向键射击的操作表。
   - [Roguelike 对局流程](RUN_FLOW.md)：当前已接入的随机直线 Level 路线、空降 5 关、总攻 6 关加固定地下要塞、GameManager 接口、进度 HUD 和测试方法；关卡递进以此处的最新规则为准。
   - [金钱与研究点数](CURRENCY.md)：敌人概率掉落、Boss 直接奖励、触碰拾取、HUD、胜败结算和持久研究账户。
   - [游戏首页](MAIN_MENU.md)：封面、图片标题、模式解锁、升级占位、音频设置与二次确认删除存档。
4. [开发与验收](DEVELOPMENT_PLAN.md)：从当前原型出发的任务顺序、完成标准与检查清单。
5. [旧稿复核](DESIGN_REVIEW.md)：哪些原型可复用、旧稿有哪些问题。

从开发清单的 **M0** 开始，每次只推进一个里程碑；不要一次性实现整份策划。

## 文档权威与状态

- 用户明确的方向：完成优先、复用原型、俯视角射击、情报驱动永久成长、独立最终任务，以及必须保留扩展能力。
- 本轮用户先选择保留旧稿已确认内容，随后允许适当降低工作量，并要求留好扩展性。本版据此把部分内容安排到 v1.1，不删除其设计与接入路线。
- **v1.0 的具体拆分、新填入的规则和数值，是本次整理给出的实施基线，不声称每一项都已获用户逐条确认。**可以直接用于开发；若用户调整，先同步文档再改代码。
- 数值是第一轮试玩起点，没有经过实机平衡验证。表中的时长是软目标，不是已测成绩。
- 玩法以 GAME_DESIGN 为准；数值以 BALANCE 为准；技术接口以 LEVEL_AND_SYSTEMS 为准；阶段进度以 DEVELOPMENT_PLAN 为准。历史稿不再参与冲突判定。
- v1.0 做完即可作为完整作品交付；v1.1 是保留的后续扩展路线，不是 v1.0 的发布前置条件，也不能提前混入当前里程碑。

## 相比旧稿的范围调整

| 内容 | v1.0 | v1.1 扩展 |
| --- | --- | --- |
| 普通流程 | 保留 3 关，6/8/10 房 | 不增加普通关卡 |
| 最终任务 | 1 个独立首领房 | 扩为 5 关，6/7/8/9/10 房，末关首领房替代出口 |
| 房间与地图 | 保留九种尺寸、分支、环路、同关不重复；使用预验证布局模板 | 增加布局和装饰；仍不做自由空间程序拼接 |
| 武器、敌人、永久成长 | 保留五枪、三敌、一首领和三项强化 | 不增加新敌种与成长系统 |
| 消耗品 | 手雷、即时医疗包 | 加燃烧瓶、盾牌 |
| 战场支援 | 暂不实现；商店接口预留 | 导弹打击、重机枪空投 |
| 失败与情报 | 情报全额结算；最终失败后重打普通三关 | 保持一致 |

本次只整理文档，未修改游戏逻辑，也未把任何系统标记为已实现。
