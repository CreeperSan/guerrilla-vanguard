# 战术装备系统

本轮被动装备共 15 件，不包含余火罐。同名不叠加，无数量上限，跨关保留；重开或回首页随玩家销毁，不写永久存档。

## 模块与边界

- `TacticalDefinition` / `TacticalCatalog`：只读定义、描述、价格、图标、能力脚本和数值。各装备一份能力脚本；新增装备无需改玩家条件分支。
- `TacticalEquipment`：玩家场景独立子组件，持有背包、按来源登记的属性修正和能力实例，分发射击、受伤、房间及闪避事件。玩家只查询通用移动倍率并发布投掷、闪避事件。
- `TacticalAbility`：独立能力对象；计时、触发次数和接触目标冷却只在对应能力内保存。删除组件时解除信号、修正及物理传感器。
- 武器读取一次射击倍率快照，成功发射后才消耗下一枪效果。弹丸数不影响触发次数。换弹开始时保存实际时长，途中获得装备不改变已经开始的换弹。
- 生命组件先执行原有闪避/主动盾过滤，再执行通用伤害修正；治疗有独立通用过滤链。能力不覆盖原过滤器。
- 房间控制器发布进入/清场事件；组件以房间实例 ID 防重复。绷带只结算战斗、战斗补给及 Boss 房。
- `TacticalReward` / `TacticalInterface` 管理 Boss 三选一、拾取确认及背包；`ShopOffer` 复用既有交易锁并增加独立战术商品类型。装备不占投掷物、支援或技能槽。

## 奖励与交互

Boss 房完全清场后在房内生成奖励箱；走近后回车 / 手柄 A / 触屏按钮查看，暂停选择最多三件未持有装备，选一件后箱子关闭。可暂时关闭面板，奖励保留到离开本关；奖池耗尽显示提示，不生成重复装备。抽取使用房间种子的独立 RNG。

商店在原三件补给之外增加一件未持有战术装备，已持有时禁止扣款，折扣以买入前状态计算。购买和奖励均明确展示负面效果。背包入口显示件数，支持鼠标、触屏及 T 键查看；暂停期间不推进能力计时。

## 验证

使用正式玩家、弹丸、伤害组件、商店及房间接入做场景测试，覆盖组合倍率、失败射击、霰弹枪、护盾优先级、房间去重、死亡、购买事务、重复装备和跨关生命周期。美术使用内置 imagegen 生成透明图集，按 AtlasTexture 映射，源提示词保存在资源目录。运行测试并不代替多轮实战平衡验收。

## 新增与调整装备

1. 在 `Script/Tactical/tactical_catalog.tres` 的 definitions 数组中增加 `TacticalDefinition`，设置稳定 ID、说明、价格、图标和 parameters；这些字段可在 Inspector 编辑。
2. 能力脚本继承 `TacticalAbility`，只实现需要的事件。常驻属性用 `modify` 按自身 ID 登记，触发状态保存在自身实例中。不要改写玩家基础属性或其他能力的状态。
3. 复用现有属性/事件时无需改玩家、商店和奖励代码；新增事件应由对应战斗组件发布，再由装备容器统一分发。为新交互增加对应契约检查。

伤害组件返回本次实际扣血量，接触能力据此提交命中；Boss 换阶段同步回血不会导致增伤效果错误保留。商店使用独立退款入口退回实扣金额，不经过奖励倍率。

实现验证和预览入口见 [TACTICAL_VALIDATION.md](TACTICAL_VALIDATION.md)。
