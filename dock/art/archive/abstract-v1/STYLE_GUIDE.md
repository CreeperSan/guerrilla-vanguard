# 《Guerrilla Vanguard》美术基准 v0.2

状态：**待确认**。依据为当前 `docs/` 策划案及仓库已有像素素材。本文只定义方向，不把示意图视为已完成的资产原型。

## 1. 核心方向

**关键词：清爽、勇敢、轻量、易读。**画面采用俯视偏斜的 2D 像素卡通：可看到角色头顶和正面少量面部信息，地板保持正交俯视。参考《元气骑士》在小尺寸下的清晰剪影、简洁色块与活泼节奏，不复制其人物、图标或场景设计。

世界虽是被占领的“岚谷”，呈现方式是轻冒险而非写实战争。**角色、敌弹、UI 的绘制语言统一，场景则按环境类型改变地表材质、主色、边缘装饰和光感。**铁幕军团始终用珊瑚红与深蓝灰识别。武器、装甲和爆炸都做玩具化处理；不出现血腥、脏污肌理、密集机械零件或大面积黑灰画面。

优先级：**危险弹幕 > 玩家位置与朝向 > 敌人攻击意图 > 可交互物 > 装饰**。视觉元素在实际战斗尺寸下必须遵守这个顺序。

## 2. 造型语法

| 类型 | 主要形状 | 识别要点 |
| --- | --- | --- |
| 玩家“前哨”空降兵 | 圆角方头 + 短梯形身体 | 薄荷绿头盔、白色 V 形前额标记、橙色围巾；八方向都保留高亮标记或围巾尾端，朝向由枪口和面罩共同指示 |
| 步兵 | 短矩形 | 珊瑚红帽/肩、细身体、一段短枪口；最窄剪影 |
| 突击兵 | 前倾三角 | 斜向护额与大号前手，动作有明显冲刺倾向；不靠颜色单独区分 |
| 重装兵 | 宽方形 | 宽肩双护甲片、矮而厚的身体；至少比步兵宽 25% |
| 要塞指挥官 | 六边形/层叠方形 | 固定中心的大轮廓、双侧通信天线、胸前单个明亮信号核；二阶段信号核变亮并有外环，不改变碰撞读法 |
| 友方物资 | 圆角方/圆形 | 青绿或金色容器、清楚的白色符号；与敌方红色弹幕分离 |
| 场景装置 | 简单大块几何 | 墙、门、商店、武器箱靠轮廓和单一图标识别，细节限于 1–2 处 |

角色以**头:身体约 1:1** 为主；重装兵可到 1:1.3，首领作为非普通人形装置不强制套头身比。普通角色原型建议先用 **24×32 px 画布**，可见形体约 22×27 px：头 12–13 px、身体含脚 13–14 px、其余留给描边与移动余量。重装兵可用 32×32 px，首领约 64×64 px。此为绘制起点，须在 Godot 房间中按碰撞与视觉比例验证，不反向改策划中的世界像素数值。

线条：主轮廓 1–2 个源像素宽，用深蓝灰 `#263F52`，避免纯黑。内部线只保留脸、胸前标识和武器朝向。每个资产主体最多 3 个明度层级（底色、暗面、高光）；禁止颗粒噪点、渐变金属反光和复杂花纹。圆角通过阶梯状像素轮廓形成，不使用模糊抗锯齿。

## 3. 色彩基准

| 用途 | 色值 | 规则 |
| --- | --- | --- |
| 深色描边/文字 | `#263F52` | 比纯黑柔和；用于角色外缘和 UI 正文 |
| 地板主色 | `#F4EBCF` | 最大面积、低纹理密度 |
| 地板暗格 | `#E5DABB` | 只作轻微分区，不制造棋盘干扰 |
| 墙体浅面 | `#8BC8C1` | 与地板有明确明度差 |
| 墙体暗面 | `#5D9F9D` | 门洞、墙脚、结构阴影 |
| 玩家主色 | `#59CFA7` | 与敌人的暖色分离 |
| 玩家辅助色 | `#FFCA70` | 围巾、互动高亮，不用作敌弹主色 |
| 敌人主色 | `#EF746B` | 三敌共用阵营色，靠形状区分种类 |
| 敌人暗色 | `#A64F65` | 护甲和首领结构 |
| 玩家子弹 | `#F8D76D` | 小而亮，配深色外圈，避免与物资同形 |
| 敌人子弹/危险预警 | `#EF5C72` | 圆心亮色 + 深色外圈；预警用虚线/扇形，不只变色 |
| 生命/治疗 | `#75D6BE` | 十字图案，不与玩家弹丸混用 |
| 情报/数据 | `#7DAFE8` | 数据片或天线符号，与物资金色分开 |
| 物资/价格 | `#F0BB58` | 六边筹码、可拾取物 |
| UI 面板 | `#FFF8E8` | 大块柔和浅色底 |

色值可在实机对比测试后小幅调整，但**玩家、敌人、弹幕、情报、物资的语义映射不可随场景交换**。上表的地板和墙体色是要塞样本；森林、沙滩、城市、乡村使用下节各自的环境色。最终首领房可降低环境饱和度，使危险预警更突出，但仍维持明亮基调。

## 4. 场景渲染体系

以已有 16 px 图块为网格基准。所有场景使用相同的角色像素密度、描边和战斗特效语法，但各有专属的**地面、边界、环境装饰、环境光色**。房间尺寸变化只拉伸/拼接对应环境的组件，不额外制作九套构图。战斗区域中心保持低对比、低细节；高对比的纹理和装饰放在边缘。场景变化不能淹没敌弹或玩家轮廓。

| 环境族 | 渲染与色调 | 边界/装饰 | 通往下一关的外观 |
| --- | --- | --- | --- |
| 地牢、要塞 | 清爽的石砖或蓝灰金属板，冷色硬边、整齐接缝；少量琥珀色灯带 | 实体墙、门框、控制台 | **门口**：打开后的门洞和向外箭头；封锁时门板合上、轮廓断开 |
| 森林 | 浅草绿地表，疏密有别的草簇和树影；暖阳斑点只落在非战斗重点区 | 树列、灌木、矮木栅栏 | **路牌**：明确箭头和下一地区短名；互动后沿林间小径切换 |
| 沙滩、海岸 | 奶油金沙、浅青海水、弧形海浪边；贝壳/漂流木稀疏点缀 | 岩石、沙丘、护栏或水边 | **路牌**：木牌和箭头，旁边可见向外延伸的沙路；不要用海浪冒充可进入区域 |
| 城市 | 浅灰蓝路面、整齐路缘、块状建筑投影；少量招牌与交通线 | 楼体外缘、路障、围栏 | **马路**：连续车道/人行横道通向画面边界，出口箭头落在路面上 |
| 乡村 | 暖土路、浅草、木栅栏和小块田地；自然但仍保持图块清晰 | 篱笆、谷仓墙、草垛 | **马路**：连续乡间道路通向边界，可用里程桩辅助指向 |

这三类出口是**同一个“前往下一关”交互规则的不同视觉外壳**：都显示目的地名称、`E` 提示、确认面板；未清战斗房时保持阻断状态。门是关闭/开启，路牌是箭头灰显/亮起且小径可见，马路是路障拦截/移开。不可只靠换色表示解锁。普通第 3 关的出口执行撤离结算，仍依所在环境使用相应外观；首领胜利直接结算，不额外画出口。

**当前三关的建议落点**：外围哨站用森林边缘，补给营地用乡村道路，通信要塞用冷色要塞。沙滩、城市、地牢保留为可复用环境族，待关卡策划实际安排后再进入完整素材量产。这样先验证三种不同出口形式，再扩充环境。此映射尚待本步确认；若三关地点要改，可替换环境族而不改出口规则。

商店用小旗 + 购物袋图标，武器库用开盖箱 + 枪形图标；基础功能图标跨场景一致，底座和外框随环境换材质。装饰无碰撞，且不绘成可拾取或可躲藏的假物件。角色脚下使用短椭圆硬边阴影帮助定位；射弹、落点与爆炸范围在地面层显示清晰边界。爆炸可鲜艳，但遮挡角色/敌弹的满屏白闪不超过瞬间。

## 5. 动效与战斗可读性

- 玩家移动可用 4–6 帧轻弹跳；枪口闪光 1–2 帧；受击以轮廓闪白/短暂透明交替，不改变阵营主色。朝向必须在停步时保留。
- 敌人开火前：步兵枪口和前额红点同步闪；重装兵的双护甲片收拢；突击兵在地面给出短距离扇/线形提示。首领单发给线形提示、三发给扇形提示。预警形状与最终判定区域一致。
- 玩家子弹为小型金黄尖头/短条；敌弹为较大的珊瑚红圆点，带深色外沿。两方轨迹不可只靠颜色区分。爆炸为橙黄圆环，治疗为青绿十字粒子，数据上传为蓝色上行像素。
- 交互对象在 32 px 范围内显示 `E` 提示；不能领取时降低亮度并给文字原因。普通物资接触自动拾取，不显示虚假的 `E` 提示。
- HUD 使用暗色文字和浅色底板。生命用心形或十字旁数值、弹药用清晰数字、枪槽显示 1/2/3；本轮物资（金六边）、本轮情报（蓝数据片）图形与名称同时出现。紧急装填提示要完整可读。
- 以 **1×原生分辨率** 和 **2×整数放大**检查：8 方向朝向、三种敌人、两方弹幕、生命/弹药/货币均可辨；关掉颜色后仍能靠轮廓/图标完成区分。测试时让 3–5 名敌人和弹幕同屏，避免只检查静态单体。

## 6. 制作与交付约定

源图按整数像素绘制，Godot 采用 nearest 过滤与整数倍显示；不在贴图中预先加入模糊、投影或字母说明。角色动画和游戏碰撞分开配置。透明底 sprite 保留 1–2 px 安全边，图集标注尺寸、锚点、方向、帧序与用途。

第 2 步原型图计划覆盖：玩家八方向、三敌与首领、五枪、医疗包/手雷/弹药箱/物资、三类出口（门口/路牌/马路）与阻断/解锁状态、各环境族地表和边界组件、商店/武器库、敌我弹幕/前摇/爆炸/治疗效果、HUD/指挥部/商店/结算。v1.1 燃烧瓶、盾牌、导弹与空投在原型清单里保留扩展标记，首版画面不出现未实现的按钮。

第 3 步才制作完整实机画面渲染图，至少展示森林/乡村/要塞三关中的不同场景与首领房，并核对 UI 对策划数值与操作的表达。所有定稿放在 `docs/art`；若方案被否决，再移至用户指定的 `dock/art/archive`。
